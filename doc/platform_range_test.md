# 平台角度范围测试

测试脚本 `test_platform_range.py` 配合当前的 `Stewart_py_v1.ino` 使用，无需换烧校准固件。
自动边界实机测试已停用：2026-11-11 的实机运行报告胶接处被拉脱。逆运动学有解及舵机指令在 0–180° 内不足以证明机构可运行。`--auto --send` 在打开串口前直接退出，自动规划仅保留离线分析。

维修期间关闭舵机电源并支撑平台；不要复位或运行回中位命令拉扯损坏机构。下文的人工测试命令也不适用于维修中的机构，历史测试结果不再作为当前机械状态的依据。

## 开始条件

- 使用正式控制固件，舵臂安装零位和转动方向已核对。
- 关闭其他 Python 播放程序与 Arduino 串口监视器。
- 平台从已校准的模型工作中位开始，红臂从水平抬起约 19.4°。
- 若当前停在回放末尾，先关舵机电源、支撑平台并检查间隙，再复位 ESP32、重新上电确认工作中位；不要在卡住时复位使其强行回中位。
- 留出球头、连杆、线缆间隙，电源开关在手边；运行时不把手伸入机构。

## 离线预演

```powershell
python test_platform_range.py
```

没有 `--send` 时不打开串口。默认零平移，扫描滚转、俯仰正负方向，步长 0.5°，最大请求角度 15°，使用当前舵机测试窗口 60–120°。
该几何下步长为 0.5° 的离线最后通过点约为滚转 +8°/−5.5°、俯仰 +6°/−6°；不是实测运动范围。

## 自动路径离线分析（实机发送已禁用）

仅计算完整去程和回程，不打开串口：

```powershell
python test_platform_range.py --auto --max-angle 90 --servo-min 0 --servo-max 180
```

该命令把舵机指令窗口设为 0–180°，对应以 90° 为中心的 ±90°；上平台的倾角仍受连杆几何限制。这个窗口是操作者选择的指令范围，不证明舵机实际全行程和球头间隙已经验证。
当前几何、0.5° 搜索步长下，模型最后通过点约为滚转 +37°/−26°、俯仰 ±26.5°。默认向内留 `--boundary-margin 2` 度，实际自动测试目标为滚转 +35°/−24°、俯仰 ±24.5°。数值仅适用于零平移、各轴单独测试。

上述目标不是允许执行的机械极限。2° 的平台角余量没有经过关节摆角、干涉和承载验证。即使改为 20–160° 窗口，也不构成机械可行性验证。任何 `--auto --send` 组合均被脚本拦截，旧运行命令也不会打开串口。

## 本次事故核对

记录 `motion_capture/range_test_20261111_221109_991573.json` 表示正滚转 +35° 的去程和回程发送完毕并收到命令回显；负滚转 -24° 的去程中断。没有实测角度或逐帧记录，无法从该文件确定损坏发生时的姿态、受力点或已到达的角度。

设逆运动学输出依次为 a1…a6（角度），固件对应 PCA 通道 0…5 的指令为：

```text
[90+a6, 90-a5, 90+a4, 90-a3, 90+a2, 90-a1]
```

Python 检查与固件代码的顺序、符号一致。这仅是软件一致性，没有验证实体通道与模型六条腿的对应关系、安装方向或真实舵机角度。

| 模型滚转 | 通道 0…5 的舵机指令（°） |
|---|---|
| 0° | 109.4, 70.6, 109.4, 70.6, 109.4, 70.6 |
| +35° | 163.7, 54.4, 22.9, 157.1, 125.6, 16.3 |
| -24° | 80.6, 84.3, 160.9, 19.1, 95.7, 99.4 |

固件在 120 Hz 下计算 `count = int(250 + 指令角/180 * 898)`。名义脉宽为 `count / (120*4096)` 秒，0–180° 对应约 509–2336 μs；这不是测量所得的实际角度标定。+35° 目标的通道 5 名义脉宽约 673 μs。PCA 时钟误差和实体舵机特性还会影响真实输出，不能由该公式保证行程。

恢复运行前需要先修复并检查固定件，核对实体六通道与模型腿的对应、各舵机零位/方向/脉宽行程，以及装配后球头摆角和连杆干涉；旧模型边界不作为重新运行的依据。本次没有更改固件脉宽或频率，也没有执行任何实体动作。

## 人工逐步测试

先测试滚转：

```powershell
python test_platform_range.py --port COM7 --axis roll --send
```

完成后测试俯仰：

```powershell
python test_platform_range.py --port COM7 --axis pitch --send
```

程序每次将平台目标改变 0.5°，速度为 1°/秒，再停下等输入。

- 回车：确认**当前位置**有足够间隙，并允许向下一档推进；到最终位置后回车确认该位置并回中位。
- `b` 回车：当前位置尚未确认或间隙偏小，缓慢退回之前确认的位置，结束这个方向并回中位。仅在机构仍自由运动时使用。
- `q` 回车或 Ctrl+C：停止发送、保持当前位置，不自动回中位。保持仍会使舵机受力，遇到接触、卡滞或异响应关闭舵机电源。

每次移动前，程序先检查整段插值路径的逆运动学与四舍五入后的舵机目标范围。
程序需要固件持续发送 `Angles:` 回显，并核对移动结束的目标值；没有反馈就停止后续发送。
固件回显只证明接收/解析了命令，未测量实体舵机或上平台的位置。运行中停止不会切断舵机电源。

## 没有串口回显时

```powershell
python test_platform_range.py --port COM7 --diagnose
```

此模式只读取串口，不发送任何动作命令。打开端口仍可能因开发板的自动复位电路而触发固件启动，运行前确认机构没有卡住。
程序从打开串口起监听 8 秒并保留启动信息，区分零字节、非标准输出和有效的 `Angles:` 回显。

- 零字节：在 Arduino 串口监视器中选 COM7/38400 检查。核对板上实际烧录的固件、供电和端口；本项目正式固件的 `Serial.begin(38400)`、`showAngles()` 调用应启用。
- 有输出但没有有效 `Angles:`：根据诊断样例检查是否为校准固件、波特率错误或 ESP32 重启输出。
- 有角度但与命令不匹配：程序停止发送，不绕过回显验证。
- 检查后关闭串口监视器，再重新执行测试。需要重烧正式固件时，先支撑平台并断开舵机电源，防止烧录/复位时跳回工作中位。

## 记录与解释

结果自动写入 `motion_capture/range_test_日期_时间.json`：

- `last_confirmed_command_deg`：人工已确认的最后目标角。
- `pending_command_deg`：尚未确认的位置；中断时可能仅部分到达。
- `stop_reason`：人工停止、请求角度达到或软件角度超限。
- `returned_home`：程序确认发完回中位命令并收到回显。

自动模式另记录 `target_deg`、`phase` 和已完成去程的 `last_completed_command_deg`。`operator_clearance_confirmed` 固定为 false，表示没有逐步人工确认；中断时 `phase` 表示发生在去程、边缘停留还是回程，均不代表实测位置。

建议在观测边界内留余量再确定工作范围；真正的倾角需要 IMU/倾角仪/视觉测量。
测试零平移、单一旋转轴。各轴单独通过，不代表滚转、俯仰、平移组合一定通过，应对完整目标轨迹单独预演和检查间隙。

## 舵机测试窗口

默认 60–120° 是软件窗口，并非硬件固有限制。脚本支持 `--servo-min`、`--servo-max`，但扩大窗口前需先核实舵机脉宽标定、安装行程和球头间隙。
本测试不会自动扩大窗口，也不修改正式回放脚本的限制。
